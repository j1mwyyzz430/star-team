# 覺醒全畫面演出設計

範圍：重做小星星、大星星、彩色星星三種互動演出，以及全班演出。沿用現有角色原畫、學生頭像與錄音；不生成新音樂、不改資料或解鎖條件。畫風來源為本專案神獸／星核機甲原畫；設計參照 fy-code-animation 的構圖、動作及分層驗證方法，實作程式為本專案新寫。

| 事件 | 畫面與動作 | 節奏 |
| --- | --- | --- |
| 小星星 | 原畫滿版推近、大頭像側邊登場，環形光帶與主色流星帶出 +1 | 約 2.1 秒，短暫進場、清楚停留、柔和退出 |
| 大星星 | 頭像移到中央，召喚陣展開、金色巨星成形，能量衝擊向外擴散 | 約 3.2 秒，先聚合再展開，保留姓名閱讀時間 |
| 彩色星星 | 滿版光譜、中央大頭像、星冠與多層星軌，粒子煙花沿邊緣綻放 | 約 4.4 秒，蓄勢、加冕、慶祝；第 3 階段才顯示終極星冠 |
| 全班 | 符合解鎖條件者各有自己的角色原畫與頭像；每屏最多 6 人，直向最多 4 人，分批顯示全部 | 每批沿用該事件節奏，可隨時按略過 |

角色色彩決定光環、粒子及光束色；三種事件有不同構圖、粒子運動和起落節奏。學生臉部和姓名留清楚閱讀區，動態不使用快速全畫面明暗閃爍。聲音沿用現有個人加分錄音及全班同步播放，不額外生成或疊加背景音樂。

畫面以同一個經過時間驅動 Canvas 和暫停後定位的 DOM 動畫，便於抽查進場、中段、落穩及收尾。離開頁面、關閉動態或按略過會取消動畫；減少動態偏好沿用原規則。圖片失敗仍顯示角色色背景及學生姓名，音訊和存分各自獨立。

全畫面使用瀏覽器 top layer，覆蓋可視 viewport，兼顧安全邊距。全螢幕按鈕在瀏覽器允許時要求整個文件進入原生全螢幕；iPad Safari 不支援的情況，提示加入主畫面使用。網頁不能強制遮蓋系統時間列或瀏覽器網址列。

## 驗證（2026-11-20）

- `node --test tests/*.test.cjs`：28 項通過，包括資料儲存、音效排程及 Google 前端鏡像一致性。
- `python3 tests/browser_rewards.py`：桌面及 iPad 模擬各 44 個等級／解鎖邊界案例通過；混合班別加分、預覽不改資料、抽獎與存分正常。
- `python3 tests/browser_awakening.py`：Chromium 的 1280×822、1024×768、820×1180、390×844、844×390 通過。另停用 Popover API 驗證 dialog 替代顯示。檢查滿版邊界、正圓頭像、三種演出進場／中段／退出的時序、19 人完整分頁、第二階段不顯示終極冠、略過／Escape、圖片失敗及減少動態偏好。實際全班按鈕確認只有符合條件的 5 位學生演出，低等級學生仍正常加分，缺席及分數上限者不變。另測自動結束、旋轉尺寸及離開頁面取消。
- `python3 tests/browser_student_audio.py`：桌面及 iPad 模擬的真實 Web Audio 排程時間相同，分數／經驗正確，靜音、個別／分組播放、預覽及重載通過。
- 人工檢視合成頭像的橫向／直向畫面及小星、大星、彩星代表幀。圖片和截圖只留在臨時目錄，不包含真實學生資料。

限制：這些是 Chromium 尺寸與觸控模擬、動畫時間取樣及靜幀檢視，未以實體 iPad Safari 審片，也未評定課室喇叭的實際聽感。GitHub Pages 線上部署狀態需另行確認；Google Apps Script 的備援前端若使用中，須更新 `google-backend/Index.html` 後重新部署，`Code.gs` 不需修改。
