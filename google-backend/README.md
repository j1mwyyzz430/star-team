# 在原有 Google 後台啟用 90 天記住登入

前端現在可保存登入憑證，重開頁面時自動讀取原有分數，不保存老師密碼。附件中的舊後台將憑證限制為 12 小時；只更新 GitHub 前端時，記住登入也只能維持至該憑證到期。

本目錄的 `Code.gs` 以老師提供的 ZIP 內後台程式為基礎，只有三處登入相關修改：接受 `remember` 參數、傳遞該參數，以及將有勾選「記住這部裝置」的有效期設為 90 天。沒有勾選時維持 12 小時；密碼驗證、簽章、資料儲存、版本衝突、照片與報表程式保持原樣。這個檔案沒有老師密碼、試算表 ID、學生備份或私人照片，這些值仍只在你原有的私人 Google 專案及試算表內。

## 更新原部署

1. 開啟**現正使用的原有試算表**，選「擴充功能 → Apps Script」。
2. 若目前 `Code.gs` 仍是附件提供的版本，可使用本目錄的 `Code.gs` 更新該檔案。**保留原有的 `Index.html`，不要刪除其他檔案。**若後台另有自訂修改，使用下方的三處修改，避免覆蓋自訂程式。
3. 儲存程式。**不要執行 `setup_` 或「首次設定／更改密碼」；本次不需要初始化、建立試算表或匯入備份。**
4. 選「部署 → 管理部署」，找出目前網站使用的原部署，按鉛筆編輯，選「版本：新版本」，再按「部署」。**不要選「新增部署」**，原有 `/exec` 網址應保持不變。
5. 等 GitHub Pages 前端更新完成，在每部裝置以一般瀏覽模式開啟原網站，輸入原有老師密碼並保留「記住這部裝置」勾選。更新前已簽發的憑證仍依原期限到期；新登入才取得 90 天憑證。
6. 重新整理或關閉後重開頁面，應自動載入原有資料，不再要求輸入密碼。各裝置首次仍需各自登入一次；90 天到期、清除瀏覽器儲存或憑證被後台撤銷後需重新登入。瀏覽器阻擋儲存時，網頁會提示無法記住登入；不要使用無痕模式來保存長期登入。

此工作階段沒有你的 Google Apps Script 編輯權限，因此只完成及測試了程式，**尚未替你部署 Google 後台**。更新 GitHub 不會自動更新 Apps Script。

## 保留自訂後台時的三處修改

在原 `Code.gs` 中保留其他所有程式，只作以下替換：

```js
// 1. 原本：function login_(password){
function login_(password,remember=false){

// 2. login_ 裏面，原本：const expiry=String(Date.now()+12*3600000);
const expiry=String(Date.now()+(remember?90*24*3600000:12*3600000));

// 3. starApi 裏面，原本：if(req.method==='login')return login_(req.password);
if(req.method==='login')return login_(req.password,req.remember===true);
```

以上是三個不同位置的替換，**不要把整個範例直接貼在檔案末尾**。老師密碼仍只在登入畫面輸入，不要填進程式碼。

## 忘記此裝置的登入

網站「設定 → 忘記這部裝置的登入」只移除此瀏覽器保存的登入憑證，然後重新顯示登入畫面。不會刪除 Google 資料、學生照片或 IndexedDB 中的個人錄音；有未儲存分數時會先阻止操作。此操作不會撤銷其他裝置已簽發的憑證。

網站及其網址可以公開取得；真正的資料保護仍由原後台的老師密碼與登入憑證提供。本次沒有加入匿名讀寫入口，也沒有把老師密碼或共用登入憑證放進公開程式。
