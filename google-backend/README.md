# 更新原有 Google 後台：班別管理及記住登入

本次班別新增／改名／刪除、學生刪除及每班 100 人，需要同時更新原 Apps Script 專案。GitHub 推送不會自動部署 Google 程式；未更新時，網站仍可載入原資料及加分，但會提示先更新後台才可管理班別及刪除學生。

## 更新原部署

1. 開啟**現正使用的原有試算表**，選「擴充功能 → Apps Script」。先在自己的私人位置保留現有程式副本。
2. 用本目錄的 [Code.gs](Code.gs) 更新原 `Code.gs`，用 [Index.html](Index.html) 更新原 `Index.html`。這次兩個檔案都要更新，Google 備用入口才會使用同一版班別功能。若曾另外修改後台，先比對合併自訂程式。
3. 儲存。**不要執行 `setup_` 或「首次設定／更改密碼」**；不需要建立試算表、清空資料、匯入備份或更改老師密碼。
4. 選「部署 → 管理部署」，編輯目前使用的原部署，選「版本：新版本」，按「部署」。**不要新增部署**，原 `/exec` 網址維持不變。
5. 等 GitHub Pages 發佈完成，各裝置完成正在儲存的操作後重新整理網站。核對原有班別、學生、照片、分數及禮物，再使用新功能。既有有效登入憑證可繼續使用。

目前沒有 Google Apps Script 編輯權限，維護工作只提交及測試了程式，**尚未代為部署 Google 後台**。

## 資料相容性

- 原有 `p1`–`p6` 班別及學生編號保持原樣；舊年級名稱成為預設班別名稱，可在「管理班別」改名。
- 新班別及新學生使用獨立 UUID。刪除或改名不會重新編號，因此禮物及本機錄音不會指向其他學生。
- 班別名稱保存在同一份狀態的 `extras.classNames`；最多 30 班，每班 100 人。原有 14 MB 狀態上限保留，包含照片及共用禮物圖片；儲存失敗時保留分頁並按提示處理。
- 已完成兌換紀錄保留刪除時的姓名／班別名稱。待派發禮物須先派發或取消退款，才可刪除相關學生或班別。
- 刪除可在同一頁、未切班或重新載入前按「撤銷」復原。刪除最後一班後可直接新增班別。禮物、庫存及抽獎權重不會隨班別刪除。
- 個人錄音仍在各瀏覽器 IndexedDB；刪除學生時暫保留其本機錄音，以便撤銷恢復，且新學生不會沿用它。完整備份仍包含本機錄音，請私人保存。
- 新前端儲存後會標記狀態格式版本 2。後台拒絕舊前端再寫入，提示重新整理，防止舊版覆蓋新班別資料。**已使用新班別功能後，不應單獨回退到舊 `Code.gs` 或舊前端**；保留本版的資料格式支援，再以後續修正提交處理問題。Git 歷史可比較及回復程式，但不會自動回復 Google 資料。
- 新完整備份格式為 `star-team-v6`，含班別名稱及永久學生編號。仍可讀取舊備份，但日常升級不需匯入任何備份。
- 學生報表保留原七欄順序，第八欄增加班別名稱；第一欄為不可修改的班別 ID。仍須由網站增刪學生，報表只套用姓名、分數、經驗、出席。

## 記住登入

勾選「記住這部裝置」時，後台簽發 90 天憑證；未勾選維持 12 小時。各裝置首次須各自登入，前端只保存憑證，不保存老師密碼。既有憑證沿用原有效期，重新登入才取得新有效期。到期、清除瀏覽器資料或撤銷後需要登入。

「設定 → 忘記這部裝置的登入」只移除本瀏覽器憑證，不刪除學生、照片或錄音。有未儲存分數時會先阻止操作。

## 維護與驗證

新前端使用 `class-tools-v2.js` 及 `portable-backup-v6.js`，保留舊檔供尚未更新的 Google 入口讀取，避免新舊介面混用。

`Index.html` 是公開前端的 Google 備用版本，使用原生 `google.script.run`。前端改動後執行 `python3 scripts/build-google-index.py`，再一起更新原 Apps Script 部署。它不包含老師密碼、學生備份或私人照片。

測試使用人工資料及模擬 Sheets／Google 請求，沒有連接或修改老師的真實資料。瀏覽器測試包含桌面及 iPad 尺寸的 Chromium 模擬，未以真實 iPad Safari 或 Google 部署驗證。
